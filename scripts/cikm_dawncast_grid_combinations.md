# DAWN-Cast — CIKM pixel-space capacity grid

All **316** combinations that pass the CIKM hard ceiling of **15,000,000** trainable parameters, plus the **68** rejected.

Generated by `scripts/dawncast_cikm_grid_report.py` from `cikm_valid_combos.csv` / `cikm_rejected_combos.csv`, which are produced by `scripts/dawncast_cikm_grid_enumerate.py` (real `sum(p.numel() ...)` counts on instantiated models, not estimates).

**Fixed:** `hidden_dim=64`, `hf_mode='separate'`, `size_factor=1.0` (resolved default), `k_spatial=3`, CIKM `T_in=5`, `T_out=10` → `hidden_size = 64*10 = 640`.

**Swept:** `level ∈ {1,2,3,4}`, `hidden_size_factor ∈ {1,2,3,4,6,8}`, `num_blocks ∈` all 16 divisors of 640.

---

## 1. How parameter count is determined (read this first)

The count is **exactly** reproduced by a closed form — checked against all 384 instantiated models, **0 mismatches**:

```
params = 6,943,129
       + 8,192,000 * (hidden_size_factor / num_blocks)
       + 6,400 * hidden_size_factor
       + 74,220 * (level - 1)
```

The `hsf/nb` term comes from the 5 `STRModule`s in each `WGTMBlock` (2 `SRSTResBlock` × 2 `SRSTBlock`, + 1 trailing). Each holds `w1, w2` of shape `(2, nb, bs, bs*hsf)` with `bs = 640/nb`, so `nb * bs * bs*hsf = 640² * hsf / nb` — the `nb` cancels except as a divisor.

The `level` term is one extra HF `FATBlock` per DWT level (because `hf_mode='separate'`), dominated by its 1×1×1 `Conv3d` fusion `2*(3*64) → 3*64` = 73,920 of the 74,220. The Gabor/MLP streams inside it act on `T_in=5 → T_out=10` only, so they contribute almost nothing.

### Three consequences that should drive the selection

**(a) `hidden_size_factor / num_blocks` is the capacity axis.** Not `nb` or `hsf` individually. It carries ~8.19M params per unit — i.e. essentially the whole budget. Everything else is rounding.

**(b) `level` is nearly free.** Each extra DWT level adds only 74,220 params — **0.49% of the budget**. Level 1 and level 4 at the same `(nb, hsf)` differ by 0.22M out of ~7–14M. So `level` is **not** a capacity knob here; it is a pure architecture knob and is almost perfectly confounded-free. It can be swept independently of the budget.

**(c) Many `(nb, hsf)` pairs are capacity twins.** Any pair with the same `hsf/nb` ratio lands within `6,400 * Δhsf` of each other — e.g. `(1,1)`, `(2,2)`, `(4,4)`, `(8,8)` are all ratio 1.0 and differ by <45k params. They are *not* the same model — `nb` sets how block-diagonal the Fourier mixing is, `hsf` sets the width inside each block — but they are indistinguishable on the parameter budget. Picking several twins spends runs without moving capacity.
